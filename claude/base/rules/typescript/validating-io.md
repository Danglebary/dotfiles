# TypeScript: validating I/O

- **Validating I/O's boundary check is one of two shared helpers, chosen by who produced the data.** Schemas stay zod, but the helpers are the single invocation point: prefer them over bare schema calls at boundaries, so every failure carries the treeified zod error (never a raw `ZodError`). Data arrives as `unknown` and is narrowed before anything consumes it. Data the program produced itself goes through `assertSchema`, which narrows the variable in place and throws an `AssertionError`, the right class for a mismatch that means the program is wrong. Data a third party produced goes through `parseSchema(value, schema)`, minted beside `assertSchema` where a repository lacks it, which returns a `kind`-keyed union — `parsed` carrying the schema's output, `malformed` carrying the treeified error — for the caller to branch on, since Assertions makes that failure a known outcome. An `AssertionError` on third-party data is always the wrong class. An `asserts` signature returns `void` and can only narrow, never hand back a new value, so a transforming schema (`.transform()`, `z.coerce`) goes through `parseSchema` whoever produced the data, and on the program's own data its `malformed` branch throws an `AssertionError` with the issues as its `cause`.
- **`.safeParse` always; `.parse` never** — inside both helpers included. `.parse` throws a raw `ZodError` at the call site, violating the treeify rule by construction and hiding the failure path; `.safeParse` returns the outcome as data, forcing the failure into an explicit `if` branch — the no-ternary and no-coalescing rules applied to validation.
- **A variable holding a zod schema is named in lower camel case ending in `Schema`** — `hookInputSchema`, never `HookInput`, `HookInputSchema`, or `HOOK_INPUT_SCHEMA`; the bare word `schema` qualifies. The suffix marks the value as a validator rather than the data it validates, so a parsed value and its schema share a stem without a reader confusing the two, and the lower camel case marks it a value, leaving PascalCase to the type inferred from it (`type HookInput = z.infer<typeof hookInputSchema>`). That type is PascalCase whether wrapped or indexed (`Readonly<z.output<…>>`, `z.infer<…>["id"]`) or not.
