# Testing

- **Test behavior, not implementation.** Assert on observable outputs and effects, not internal structure or private calls. A refactor that preserves behavior must not break tests.
- **One behavior per test.** Each case exercises a single logical unit of behavior; never bundle unrelated assertions into one case to save a test. A failing test's name should tell me what broke.
- **Table-driven when the shape fits.** Prefer one parameterized test over copy-pasted near-duplicate cases — most languages support this in some form.
- **Test-first: red → green → refactor.** Write the failing test, make it pass minimally, then clean up. If TDD doesn't fit the problem, don't force it — plan an alternative approach and present it to me before proceeding.
- **Tests exercise invalid data, not only valid.** Assertions' positive-and-negative-space rule applies to test inputs: an invalid-data case constructs its invalidity explicitly — a valid base with the broken field overridden visibly — so the test states exactly which property it violates.

## Spies

This section decides what a test may assert, and what the difficulty of writing that test is evidence of. An agent told to test a function that returns nothing reaches for the one instrument that appears to work, and produces a test that satisfies every other rule while freezing the implementation in place. A test is a measuring instrument pointed at the design, and the difficulty of writing it is the reading. A spy is what gets reached for when the reading is bad.

- **A spy assertion is a design finding, not a test.** `toHaveBeenCalled`, `toHaveBeenCalledWith`, `not.toHaveBeenCalled`, `toHaveBeenCalledTimes`, a direct read of a mock's recorded calls, and every other framework's spelling of them are one instrument under many names: each asserts on a call where the assertion wanted a result. Reaching for one means a pure computation is still tangled inside an effectful function. The tangle is the finding and the assertion is the shortcut around it — a shortcut precisely because it works, so the test passes, the coverage counts, and the design defect ships behind a green check.
- **Extract the decision, then test the decision.** The computation comes out as a function taking values and returning values — the window, the identifier list, the classification, the mapping together with what it dropped — and its test calls that function directly, with no service constructed, no context, and no mock. This is Control flow's push-`if`s-up, push-`for`s-down and its helpers-compute, parents-decide split, arrived at from the test side rather than by inspection: writing the test is what makes the missing seam visible, and cutting the seam fixes the test and the design in one move.
- **Two questions, asked before the assertion is written.** What is the smallest function that could make this assertion true? Where that function is smaller than the one under test, it is the function to write and the one to assert on. And what does this assertion fail on? Where the answer is a refactor that changes no observable behavior — a rename, an inlined helper, a collaborator swapped for an equivalent — the assertion is on implementation. The second question is Comments' falsifiability test pointed at a test case rather than at a sentence.
- **Setup length is part of the reading.** An arrange block that dwarfs act and assert together measures the distance between the surface and the decision instead of the decision. Constructing a service, installing four spies, and mocking a context to check a date subtraction is a report on where that subtraction lives.
- **What survives extraction is wiring, and wiring belongs to the integration test.** Once the decisions are out, the residue fetches, hands over, and writes; it holds no decision left to assert, and every remaining did-it-call question is answered better by real rows in a real database. Cover it against real infrastructure, or leave it uncovered and say so in the PR description. Those are the two honest options.
- **Never grow a return value to make a test easier.** The shell stays returning nothing. State and scope's low-dimensional-returns ladder governs how an effectful function reports an outcome and does not reach whether a pure computation hands back what it computed; a pure function returning its result is the ladder's premise rather than an exception to it. Widening the shell so a unit test can read something is the spy's coupling run backwards, with the test dictating a production signature.
- **Effects, in the test-behavior rule's sense, are the system's, not the function's.** Rows written, a response returned, a message published, a request that reached a provider: observable at a boundary and asserted there. The calls a function makes to its collaborators are internal structure, which that rule already excludes — a spy assertion sits on the wrong side of a line the test-behavior rule drew first.
- **Test-first is where this costs nothing.** Write the test before the function exists and the pressure toward a spy arrives while there is still no implementation to refactor: the difficulty of the red step is the design review, and acting on it at that moment is free. Discovering it afterward means rewriting the test and the code together.
- **The admission is one case, and it carries its own why.** An effect the system is obliged to produce or withhold that no return value and no readable state can witness — a destructive request that must never be sent, a second network call a cache exists to prevent. Where the collaborator can be replaced by a fake whose recorded state the test reads, that fake is the instrument. Where it cannot, the spy carries a comment naming the extraction that was tried and why the effect is unwitnessable — a comment in the shape of Tooling's zero-suppressions why-comment, never a disable directive naming a rule the repository's own linter does not run. Reaching this admission twice in one file is itself the finding.
- **This binds at write time and on touch.** Existing spy assertions are not a backlog and this section is not a sweep mandate. Housekeeping sets the reach: a test that breaks on a behavior-preserving refactor is already sanctioned for rewrite, and this section supplies the diagnosis that remedy was waiting for. Anything wider is proposed, not performed.
